# 스킬 산출물 이중 아카이브

$ARGUMENTS

스킬이 만든 문서를 **옵시디언 볼트(원본)**와 **노션 DB(검색용 사본)** 양쪽에 저장한다.

> 설계 원칙: **원본은 하나다.** 옵시디언의 마크다운이 진실이고, 노션은 찾기 위한 색인이다.
> 둘이 갈라지면 옵시디언을 믿는다. 이 규칙이 없으면 "어느 쪽이 최신이지?"를 매번 묻게 된다.

**설정은 `config.md`에서 읽는다. 이 파일의 값을 하드코딩하지 말 것.**

---

## Dispatch

| 인자 | 동작 |
|---|---|
| `[파일경로]` | 그 파일 하나를 저장 |
| `[경로1] [경로2] ...` | 여러 파일을 한 번에 |
| `--session` | 이번 세션에서 만든 산출물 전부 (대화 맥락에서 수집) |
| `--notion-only` / `--vault-only` | 한쪽만 |
| `--update` | 이미 있는 항목을 덮어쓴다 (기본은 중복 감지 후 질문) |
| (빈 입력) | 저장할 문서를 묻는다 |

---

## 실행 단계

### ▶ [1/6] 대상 확정 및 사전 점검

1. `config.md`를 **먼저 읽는다.** `vault_repo`가 `<미설정>`인지 확인.
2. 저장 대상 파일 경로를 확정한다. 인자가 없으면 최근 생성된 `.md`를 후보로 제시하고 `AskUserQuestion`으로 고르게 한다.
3. **각 파일을 실제로 읽는다.** 읽지 않은 파일은 저장하지 않는다 — 내용을 모르는 채로 노션에 올리면 무엇을 배포했는지 알 수 없다.
4. 짝 문서(`_검증.md` 등)가 같은 디렉토리에 있으면 **함께 저장할지 확인**한다. 검증 리포트가 본문과 떨어지면 "검증받은 결론"이라는 정보가 사라진다.

> ✓ Gate: 파일 경로 확정 + 전문 읽기 완료 + config 로드. 미충족 시 → 중단하고 사용자에게 확인.

---

### ▶ [2/6] 메타데이터 추출

각 문서에서 다음을 뽑는다. **추측하지 말고 문서에서 찾는다. 없으면 없다고 표시한다.**

| 필드 | 어디서 찾나 | 없을 때 |
|---|---|---|
| 제목 | 첫 `# ` 헤딩 | 파일명에서 유도 |
| 생성일 | frontmatter 또는 `> 생성일:` | 오늘 날짜 (`date +%F`) |
| 스킬 | frontmatter `스킬:` 또는 본문의 스킬명 | `기타` |
| 주제 분야 | frontmatter `tags:` | `기타` |
| 검증 판정 | `PASS` / `PASS WITH FIXES` / `FAIL` 문자열 | 검증 단계가 있는 스킬이면 `미검증`, 아니면 `해당없음` |
| 근거 강도 | 최종 결론에 붙은 `[Strong]` 등의 태그 | `해당없음` |
| 한 줄 결론 | `## 결론` 또는 `한 줄 답` 섹션 | 첫 문단 2~3문장 |

**select 값은 `config.md`의 스키마 표에 있는 것만 쓴다.** 없는 값을 보내면 페이지 생성이 실패한다.
새 분류가 필요하면 `기타`로 넣고 **사용자에게 옵션 추가를 제안**한다 — 임의로 스키마를 바꾸지 않는다.

> ✓ Gate: 문서당 7개 필드 확정 (없으면 명시적 기본값). 미충족 시 → 해당 필드를 사용자에게 확인.

---

### ▶ [3/6] 옵시디언 변환

볼트용 마크다운을 만든다. 원본 내용은 **한 글자도 바꾸지 않고**, frontmatter만 정규화한다.

```yaml
---
tags: [{주제분야1}, {주제분야2}, skill-output, {스킬명}]
created: {YYYY-MM-DD}
skill: {스킬명}
verification: {검증 판정}
notion: {노션 페이지 URL}      # 4단계 후 채운다
---
```

본문 상단에 날짜 위키링크를 넣는다: `> 생성일: [[{YYYY-MM-DD}]]`
(이미 있으면 중복 추가하지 않는다.)

**옵시디언 문법 주의**:
- 위키링크 `[[...]]`는 **날짜와 실제 볼트 노트에만** 쓴다. 존재하지 않는 노트를 링크하면 빈 노트가 양산된다
- 본문의 일반 마크다운 링크 `[텍스트](URL)`는 그대로 둔다
- 파일명에 `/ \ : * ? " < > |` 를 쓰지 않는다 — 있으면 `_`로 치환

> ✓ Gate: frontmatter 정규화 + 파일명 안전성 확인. 원본 본문 무변경.

---

### ▶ [4/6] 볼트 저장 (깃)

`config.md`의 `vault_repo`가 설정돼 있으면:

1. `local_clone` 경로에 클론이 있는지 확인. 없으면 클론한다
2. `git -C {local_clone} pull origin {vault_branch}` — **먼저 당긴다.** 볼트는 다른 기기에서도 편집되므로 충돌 위험이 실재한다
3. `{vault_subdir}/` 아래에 파일을 쓴다
4. **같은 이름의 파일이 이미 있으면 덮어쓰지 않고 멈춘다.** `--update`가 없으면 `AskUserQuestion`으로 확인 — 볼트는 사용자가 손으로 편집하는 공간이고, 그 편집을 날리는 게 이 스킬의 최악의 실패다
5. 커밋 후 `git push -u origin {vault_branch}`. 실패 시 2s/4s/8s/16s 백오프로 4회까지 재시도

`vault_repo`가 `<미설정>`이면:
- `Super_KIKI/vault-outbox/`에 파일만 만든다
- 사용자에게 **"볼트 리포가 설정되지 않아 outbox에 뒀다"**고 명시하고, `config.md`의 연결 절차를 안내한다
- **노션 저장은 그대로 진행한다** — 한쪽이 막혔다고 다른 쪽까지 멈추지 않는다

> ✓ Gate: 파일이 볼트(또는 outbox)에 존재 + 커밋 해시 확보. 실패 시 → 실패 사실을 6단계 보고에 명시.

---

### ▶ [5/6] 노션 저장

**먼저 중복을 확인한다**: `notion-query-data-sources`로 같은 `제목`이 있는지 조회.
- 있고 `--update`면 `notion-update-page`로 갱신
- 있고 `--update`가 없으면 `AskUserQuestion`으로 덮어쓸지 새로 만들지 확인
- 없으면 새로 생성

`notion-create-pages` 호출:
- `parent`: `{ type: "data_source_id", data_source_id: <config의 값> }`
- `properties`: 2단계에서 뽑은 7개 + `볼트 경로`, `깃 커밋`, `상태: 완료`
- `content`: **문서 전문.** 요약하지 않는다

**노션 마크다운 주의**:
- Notion-flavored Markdown 규격은 `notion-fetch`로 `notion://docs/enhanced-markdown-spec`을 읽어 확인한다. **문법을 추측하지 않는다**
- 매우 긴 문서는 한 번에 안 들어갈 수 있다. 그때는 페이지를 만든 뒤 `notion-update-page`로 이어붙인다
- 원본 마크다운의 표·코드블록이 깨지면 **그대로 두고 보고에 적는다.** 내용을 임의로 고쳐서 맞추지 않는다 — 옵시디언 원본이 진실이므로 노션이 조금 깨져도 정보는 잃지 않는다

> ✓ Gate: 노션 페이지 URL 확보. 실패 시 → 6단계 보고에 명시하고 볼트 저장은 유지.

---

### ▶ [6/6] 상호 링크 + 보고

1. **옵시디언 파일의 frontmatter `notion:` 필드에 노션 URL을 채우고** 다시 커밋한다
2. **노션 페이지의 `볼트 경로`·`깃 커밋` 속성**을 채운다 (5단계에서 이미 넣었으면 생략)
3. 보고:

```markdown
## 아카이브 완료

| 문서 | 옵시디언 | 노션 |
|---|---|---|
| {제목} | `{볼트경로}` ({커밋해시}) | [{제목}]({노션URL}) |

- 검증 판정: {판정} / 근거 강도: {강도}
- ⚠️ 실패·부분성공이 있으면 여기에 명시
```

> ✓ Gate: 양쪽 링크가 서로를 가리킴 + 보고 출력. 한쪽이 실패했으면 **성공한 척하지 말고 실패를 적는다.**

## Hard Rules

1. **읽지 않은 파일은 저장하지 않는다.** 노션 저장은 배포다. 무엇을 배포하는지 모르면 안 된다
2. **원본 본문을 고치지 않는다.** frontmatter만 정규화한다. 노션에서 렌더링이 깨져도 본문을 손보지 않는다
3. **볼트 덮어쓰기는 반드시 확인받는다.** 볼트는 사용자가 손으로 쓰는 공간이다
4. **한쪽 실패가 다른 쪽을 막지 않는다.** 노션이 안 되면 볼트만이라도, 볼트가 안 되면 노션만이라도 저장하고 **실패를 명시 보고**한다
5. **부분 성공을 완전 성공처럼 보고하지 않는다.** "저장했습니다"는 양쪽 다 됐을 때만 쓴다
6. **스키마에 없는 select 값을 보내지 않는다.** `기타`로 넣고 옵션 추가를 제안한다
7. **검증 리포트는 본문과 함께 저장한다.** 떨어지면 "검증받은 결론"이라는 정보가 사라진다

## Edge Cases

| 시나리오 | 동작 |
|---|---|
| `vault_repo` 미설정 | outbox에 파일 생성 + 안내. 노션은 정상 진행 |
| 볼트에 같은 파일 존재 | 멈추고 확인. `--update` 있으면 덮어씀 |
| 노션에 같은 제목 존재 | 조회 후 확인. `--update` 있으면 갱신 |
| 문서가 너무 김 | 페이지 생성 후 `notion-update-page`로 분할 이어붙임 |
| frontmatter 없음 | 2단계 표의 기본값으로 채우고, 무엇을 추정했는지 보고에 명시 |
| 볼트 깃 충돌 | pull 후 재시도. 같은 파일 충돌이면 **자동 병합하지 않고** 사용자에게 넘김 |
| 노션 MCP 미연결 | 볼트만 저장 + "노션 미연결" 보고 |
| 문서에 개인 회고·감정 기록 포함 | **저장 전 사용자 승인 필수** (CLAUDE.md 7조) |

## Checklist Before Stopping

- [ ] `config.md`를 읽었다 (하드코딩하지 않았다)
- [ ] 저장 대상 파일을 **전문 읽었다**
- [ ] 짝 문서(검증 리포트 등)를 함께 처리했다
- [ ] 메타데이터 7개 필드가 스키마에 있는 값이다
- [ ] 옵시디언 frontmatter가 정규화됐고 본문은 무변경이다
- [ ] 볼트 덮어쓰기 전 확인받았다
- [ ] 노션 중복을 조회했다
- [ ] 양쪽 링크가 서로를 가리킨다
- [ ] **실패한 것을 실패했다고 보고했다**

## 다른 스킬에서 호출하기

`expert-panel`의 7단계 저장처럼, 다른 스킬의 저장 단계에서 이 스킬을 부를 수 있다:

```
Skill(skill: "archive-doc", args: "EBP_{주제}.md EBP_{주제}_검증.md")
```

호출하는 쪽은 **저장 위치를 스스로 정하지 말고** 이 스킬에 넘긴다. 저장 경로 규칙이 두 군데에 흩어지면 갈라진다.
